# Android 플랫폼 경계 구현 절차

## 원칙

이 층에서 **한글이 깨지고 파일이 유실**된다. 나중에 고치는 비용이 가장 큰 영역이므로 1일차부터 규칙을 적용한다.
서버·계정을 추가하지 않는다. 네트워크는 광고 SDK와 인앱결제 외에 사용하지 않는다.

## 1. 한글 처리 (가장 먼저 적용)

### 파일명 정규화 — `core/file_name.dart` 단일 구현

```
trim → NFC → 금지문자 치환(/ \ : * ? " < > |) → 100자 제한 → 빈 값이면 "문서_yyyyMMdd_HHmm"
```

저장 **직전**에 적용한다. 저장·공유·내보내기 세 경로 모두 이 함수를 경유해야 한다 — 한 경로라도 건너뛰면 그 경로에서만 깨진다.

파생 이름: 합치기 `<첫 문서 제목> 외 N건` / 나누기 `<원본 제목> (발췌)` / 편집 저장 `<원본 제목> (편집본)` / 중복 시 ` (2)`

### 폰트 임베딩 — `core/korean_font.dart` 단일 구현

PDF에 텍스트를 넣는 **모든** 지점에서 Noto Sans KR을 임베딩한다. 한 곳이라도 누락하면 그 지점에서 `□□□`가 출력된다.

### 경로에 제목을 쓰지 않는다

`docId`는 UUID v4다. 사용자 제목은 **DB에만** 저장하고, 공유·내보내기 시점에만 파일명으로 변환한다.
이유: 한글·특수문자 사고를 경로 층에서 원천 차단하기 위해서다.

### 고정 테스트 데이터

`2026년 8월 보고서 (최종).pdf` — 공백·괄호·한글·연도가 모두 들어있다. 검증 시 이 이름으로 추적한다.

확인 대상: 임포트 시 표시명 추출 / 저장 시 정규화 / 공유 시 카카오톡·Gmail·드라이브에서의 표시.

## 2. 외부 PDF 임포트 흐름

```
시스템 파일 선택기(SAF) 또는 외부 인텐트
  → content:// URI 수신
  → 표시명(display name) 추출
  → 앱 작업공간으로 복사 (원본 미변경)
  → 열기/보기
  → [편집] 시 "복사본으로 편집합니다" 안내
  → PageRef 목록 생성 → 편집 → 새 PDF로 저장
```

규칙:
- **원본 URI에 대한 지속 권한을 요청하지 않는다.** 복사본만 다룬다.
- 원본 외부 파일을 수정하지 않는다.
- 저장 후 "새 파일로 저장됨"을 명확히 알린다.

## 3. 인텐트 필터 (v1 필수 · 유일한 무료 유입 채널)

`AndroidManifest.xml`에 `application/pdf` VIEW 인텐트 필터를 등록해 카카오톡·메일·드라이브에서 PDF를 탭했을 때 앱이 후보로 뜨게 한다.
외부에서 전달받은 URI도 **앱 작업공간 복사본 방식으로 동일하게** 처리한다.

필터 등록만으로는 완성이 아니다. **수신 URI를 처리하는 진입 코드가 실제로 연결되어 있는지** 함께 확인한다. 이 둘이 어긋나면 앱은 후보로 뜨지만 열리지 않는다.

실기기 확인 항목(빌드 필요 → 사용자 확인 후 수행):
- [ ] 카카오톡에서 받은 PDF → 앱 후보에 뜨는가
- [ ] Gmail 첨부 → 열리는가
- [ ] 드라이브 → 열리는가
- [ ] 한글 파일명이 유지되는가

## 4. ML Kit 문서 스캐너 — `pdf/scan_source.dart`

`google_mlkit_document_scanner`는 **베타·Android 전용·Play 서비스 필수**다. 인터페이스로 감싸서 교체 가능하게 둔다.

- 플로우 호출과 결과 수신만 한다. 자체 카메라·크롭·필터 UI를 만들지 않는다.
- Play 서비스 없음/실패 → "사진 → PDF"로 유도한다. **앱이 죽지 않게 한다.**
- 폴백 경로가 실제로 동작하는지 확인한다. 폴백은 예외 처리가 아니라 정식 경로다.

## 5. 저장소 레이아웃 (`data-model.md`)

```
<app_documents>/
  docs/<docId>/
    document.pdf        최종 산출물
    sources/            원본 소스 (편집·재저장에 필요)
      src_0.pdf         외부 PDF 복사본
      pages/001.jpg     스캔·사진 페이지
  thumbs/<docId>.jpg
  recent/               최근 연 외부 파일 복사본 (용량 상한 관리)
  cache/                썸네일 캐시 (언제든 삭제 가능)
```

역할을 혼동하지 않는다:
- `sources/` — 편집 재저장에 필요. 함부로 지우지 않는다. 저장 공간 관리 화면에서만 정리.
- `cache/` — 삭제되어도 기능에 영향이 없어야 한다.
- `recent/` — 용량 상한 초과 시 오래된 복사본부터 정리.

## 6. Drift 스키마

`documents` / `pages` / `recent_files` / `settings`(단일 행) — 컬럼 정의는 `data-model.md`를 그대로 따른다.

**`pages.kind` 이원화(`image` / `pdf`)가 이 스키마의 핵심**이다. 외부 PDF 페이지를 이미지로 바꾸지 않고 원본 페이지를 그대로 참조하기 위한 구조이며, 한 문서에 두 종류가 섞인다.
`kind = pdf`일 때만 `source_index`가 있고 `image`면 null이다 — 이 제약을 스키마와 코드 양쪽에서 지킨다.

### 상태 규칙

- **원본 진실은 파일이다.** DB는 목록 조회용 인덱스이며, 불일치 시 파일 기준으로 복구한다.
- 저장 실패 시 `docs/<docId>/` 전체 롤백. 반쪽 문서를 목록에 남기지 않는다.
- 앱 시작 시 DB에 있으나 파일이 없는 문서는 목록에서 제거한다.

## 7. isolate

PDF 파싱·병합·압축은 isolate에서 실행한다. 비동기만으로는 UI가 멈춘다.
isolate 경계를 넘는 데이터는 직렬화 가능해야 한다 — 파일 경로와 원시 타입 위주로 전달하고, DB 핸들·플랫폼 채널 객체를 넘기지 않는다.

## 8. 예외 처리 (반드시 만난다)

| 상황 | 동작 |
|---|---|
| 암호 걸린 PDF | 비밀번호 입력 요청. 실패 시 보기 불가 안내 (v1은 열기만, 암호 설정은 v1.1) |
| 손상 파일 | 앱이 죽지 않고 "열 수 없는 파일" 안내 |
| 500페이지+ / 100MB+ | 진행률 + 취소. 썸네일 지연 로딩 |
| Play 서비스 실패 | "사진 → PDF" 유도 |
| 공간 부족 / 권한 거부 | 명시적 실패 처리. 무음 실패 금지 |
| 사용자 취소 | 부분 산출물을 남기지 않는다 |

## 9. 인앱결제

상품: "광고 제거" 4,900원, **비소모성 1개**. 구매 복원 지원.
`settings.ads_removed = true`면 배너·전면 모두 제거. **기능 잠금은 없다.**
구매 후 재설치 시 복원이 동작하는지 확인한다(실기기 검증 항목).

## 구현 후 자체 점검

- [ ] 저장·공유·내보내기 세 경로가 모두 `file_name.dart`를 경유하는가
- [ ] PDF 텍스트 삽입 지점 전부에 폰트 임베딩이 적용되는가
- [ ] 경로에 사용자 제목이 섞이지 않는가 (UUID만)
- [ ] `content://` 표시명 추출이 한글을 보존하는가
- [ ] 인텐트 필터와 URI 수신 처리 코드가 **양쪽 다** 있는가
- [ ] Play 서비스 실패 폴백이 실제로 동작하는가
- [ ] `pages.kind` 이원화가 스키마·모델·쿼리에 일관되게 반영되는가
- [ ] 저장 실패 시 `docs/<docId>/`가 롤백되는가
- [ ] `cache/` 삭제 후에도 앱이 정상 동작하는가
- [ ] isolate 전달 데이터가 직렬화 가능한가
- [ ] 새 패키지를 사용자 확인 없이 추가하지 않았는가
