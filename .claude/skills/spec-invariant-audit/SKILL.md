# 스펙 불변식 감사 절차

## 이 감사가 잡는 것

이 프로젝트의 결함은 문법 오류가 아니라 **불변식 위반**의 형태로 나타난다. `flutter analyze`가 통과하고 빌드가 성공해도 제품이 죽는다.
래스터화 한 줄, 게이트 우회 한 줄, 폰트 누락 한 곳, 중복 구현 하나가 전부 그런 결함이다.

## 0. 검사 계획 승인 (착수 전 필수)

**검증을 바로 시작하지 않는다.** 먼저 계획을 제시하고 사용자 승인을 받는다.

제출 형식:

```markdown
## 검사 계획 — 라운드 N
| 항목 | 내용 |
|---|---|
| 검사 범위 | (파일·모듈 목록) |
| 검사 항목 | (아래 5개 영역 중 선택 + 선택 이유) |
| 검사 방법 | (grep 패턴 / 양쪽 동시 읽기 대상 / 실행 스크립트) |
| 제외 항목 | (보지 않는 것 + 이유) |
| 예상 산출물 | _workspace/{phase}_spec-guardian_report.md |
```

사용자가 범위를 조정하면 조정된 범위로만 수행한다. 승인 없이 범위를 넓히지 않는다.
**예외:** 검사 중 절대 규칙 위반이 우연히 발견되면 계획 범위 밖이어도 즉시 보고한다. 규칙 위반 보고는 승인 대상이 아니다.

## 검사 시점 (사용자 승인 방식 · 2026-08-17)

**모듈 완성 직후 점진 검사(incremental)**가 고정 방식이다. 전체 완성 후 1회가 아니다.
경계면 불일치는 후속 모듈로 전파되므로, 늦게 잡을수록 수정 비용이 커진다.

**1라운드는 코드가 아니라 설계 산출물을 검사한다** (`_workspace/01_architect_design.md`). 코드가 생기기 전에 구조적 위반 여지를 봉쇄하는 것이 가장 저렴하기 때문이다.

### 설계 산출물 검사 항목 (1라운드 전용)

코드가 없으므로 grep이 아니라 **설계가 위반을 가능하게 하는가**를 본다.

| 확인 | 위반 신호 |
|---|---|
| 저장 경로가 렌더 API에 접근할 수 있는가 | `PdfEngine`이 `PdfRenderer`에 의존하도록 설계됨 |
| `size_guard`를 우회할 저장 경로가 있는가 | 게이트를 거치지 않는 저장 진입점이 설계에 존재 |
| 게이트 결과가 사용자에게 도달하는가 | 위반이 예외(`throw`)로만 표현되어 상위에서 삼켜질 수 있음 |
| 6개 단일 소유 파일의 책임이 겹치는가 | 같은 기능이 두 파일의 책임으로 기재됨 |
| `PageRef` 이원화가 모든 소비 지점에 반영되었는가 | 저장·렌더·편집 중 한 곳이라도 단일 종류만 가정 |
| 폰트 임베딩·NFC 정규화가 모든 경로를 덮는가 | 저장·공유·내보내기 중 누락 경로 존재 |
| 광고 수치가 확정되었는가 | 배너 높이·완충 밴드·하단 패딩이 미정이면 오터치 방지가 구현 시점에 즉흥 결정됨 |
| isolate 전달 데이터가 직렬화 가능한가 | DB 핸들·플랫폼 객체가 경계를 넘도록 설계됨 |
| 스펙 외 요소가 설계에 들어왔는가 | v1 제외 항목(정렬 옵션·검색·다크모드 등)이 설계에 존재 |

지적 사항은 `pdf-architect`가 설계에 반영한 뒤 구현을 시작한다.

## 영역 1. 절대 규칙 9개

| # | 규칙 | 검사 방법 |
|---|---|---|
| 1 | 서버·계정 없음 | `http`/`dio`/`firebase`/`supabase`/`auth`/`login` grep. 광고 SDK·`in_app_purchase` 외 네트워크 발견 시 위반 |
| 2 | 래스터화 금지 | `pdf_engine.dart`에서 `render`/`toImage`/`Bitmap`/`Canvas` grep. **`pdf_engine.dart`가 `pdf_renderer.dart`를 import 하면 그 자체로 위반 신호** |
| 3 | 용량 초과 시 저장 중단 | 모든 저장 진입점이 `size_guard`를 경유하는가. 결과를 `ignore`/빈 `catch`/주석으로 무력화하지 않는가 |
| 4 | PDF 텍스트 수정 금지 | 텍스트 편집·주석·서명·형광펜 관련 코드 |
| 5 | 자체 카메라·보정 UI 금지 | `camera` 패키지, 자체 크롭·필터 위젯 |
| 6 | 원본 외부 파일 미수정 | `content://`에 대한 쓰기, `takePersistableUriPermission` 호출 |
| 7 | 광고 지점 제한 | `AdWidget`/`BannerAd` 사용처가 `banner_host.dart`를 경유하는가. 스캔·파일선택기 화면에 없는가 |
| 8 | 스펙 외 기능 금지 | 5개 화면 외 화면, 정렬 옵션·검색·다크모드·OCR 등 v1 제외 항목 |
| 9 | 임의 빌드 금지 | 사용자 확인 없이 `flutter build`/설치가 실행된 흔적 |

## 영역 2. 중복 금지 6개

| 기능 | 단일 소유 파일 | 탐지 키워드 |
|---|---|---|
| 저장 경로 | `pdf/pdf_engine.dart` | `save`, `merge`, `split` |
| 렌더·썸네일 | `pdf/pdf_renderer.dart` | `render`, `thumbnail`, `toImage` |
| 파일명 정규화 | `core/file_name.dart` | `NFC`, `normalize`, 금지문자 치환 |
| 한글 폰트 로딩 | `core/korean_font.dart` | `NotoSans`, `loadFont`, `ttf` |
| 용량 검증 | `core/size_guard.dart` | `lengthSync`, `fileSize`, `1.05`, `1.2` |
| 배너 배치 | `ads/banner_host.dart` | `BannerAd`, `AdWidget`, `AdSize` |

**판정:** 해당 로직이 소유 파일 **밖에서** 발견되면 위반. 소유 파일을 호출하는 것은 정상, 재구현은 위반.
비율 상수 `1.05`/`1.2`가 `size_guard.dart` 밖에 있으면 게이트가 조용히 완화되고 있다는 신호다.

## 영역 3. 경계면 교차 검증 — "양쪽을 동시에 읽어라"

한쪽만 읽으면 이 결함은 잡히지 않는다. 각각은 정상인데 연결이 어긋나는 유형이다.

| 검증 대상 | 왼쪽 (생산자) | 오른쪽 (소비자) | 흔한 불일치 |
|---|---|---|---|
| 엔진 API 계약 | `pdf_engine.dart` 시그니처 | `features/edit/` 호출부 | 진행률·취소 누락, 에러 타입 미처리 |
| 게이트 결과 | `size_guard` 반환 타입 | 저장 흐름 분기 | 위반을 사용자에게 전달하지 않고 삼킴 |
| Drift 스키마 | `data/db/` 컬럼 | Repository·UI 모델 | `kind`/`source_index` 매핑 누락 |
| **PageRef 이원화** | `page_ref.dart` sealed 분기 | 저장·렌더·편집의 분기문 | `ImagePageRef`만 처리 → **혼합 문서 붕괴** |
| 파일명 정규화 | `file_name.dart` | 저장·공유·내보내기 호출부 | 공유 경로에서 정규화 건너뜀 |
| 저장소 레이아웃 | `data-model.md` 경로 규약 | `storage/` 실제 경로 | `sources`/`recent`/`cache` 역할 혼동 |
| 배너 높이 | `banner_host.dart` 선점 높이 | 화면별 스크롤 하단 패딩 | 패딩 < 배너 높이 + 밴드 → **오터치** |
| 인텐트 필터 | `AndroidManifest.xml` | URI 수신 처리 코드 | 필터만 있고 처리 경로 없음 |

**`PageRef` 분기 누락이 1급 위험**이다. 한 문서에 두 종류가 섞이므로 모든 `switch`/`if`가 두 종류를 다루는지 전수 확인한다. `default:`/`_:`로 뭉갠 분기는 컴파일러 보호를 없앤 것이므로 위반으로 본다.

## 리포트 형식

```markdown
## 위반 (즉시 수정)
- [규칙 2] lib/pdf/pdf_engine.dart:88 — 저장 경로에서 renderPage() 호출
  담당: pdf-core | 수정: 페이지 객체 import로 대체

## 경계면 불일치
- [PageRef] lib/features/edit/save_flow.dart:42 ↔ lib/pdf/page_ref.dart:12
  담당: flutter-ui + pdf-core (양쪽 통보)

## 확인 필요 (근거 부족)
## 해소됨 (이전 라운드 지적)
## 통과
```

**"확인 필요"를 "통과"로 적지 않는다.** 확인하지 못한 항목은 확인하지 못했다고 쓴다.
거짓 양성이 반복되면 팀이 리포트를 무시하게 되므로, 확신이 없으면 "위반"이 아니라 "확인 필요"로 분류하고 근거를 적는다.

## 재발 대응

같은 위반이 2회 이상 재발하면 개별 수정 요청 대신 **설계 또는 하네스 수정**을 제안한다. 반복 위반은 사람의 부주의가 아니라 구조의 결함이다.
