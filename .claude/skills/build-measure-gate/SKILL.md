# 빌드·측정 실행 절차

## 0. 빌드는 임의로 실행하지 않는다 (절대 규칙 9)

다음은 **매번 사용자 확인**을 받는다:

- `flutter build apk` / `appbundle` — 실행 여부, APK/AAB 선택
- 버전 업 (`pubspec.yaml` version)
- 실기기 설치 (`flutter install`, `adb install`)
- 릴리스 서명 빌드

확인 없이 실행해도 되는 것: `flutter analyze`, `flutter test`, `flutter pub get`(기존 의존성 한정), 파일 크기 측정, 로그 수집.

의심스러우면 실행하지 말고 묻는다. 실행하지 않은 것은 되돌릴 수 있지만, 설치·배포된 것은 되돌릴 수 없다.

## 1. 비밀값 취급 (`F:\keys\PDF_daeri`)

키·서명 자료·광고 및 결제 ID는 **리포지토리 밖의 `F:\keys\PDF_daeri`에 보관**한다.

| 파일 | 용도 |
|---|---|
| `.env` | AdMob 앱 ID·광고 단위 ID, 결제 관련 ID 등 |
| `release.jks` | 릴리스 서명 키스토어 |

### 규칙

1. **비밀값을 절대 리포지토리에 복사하지 않는다.** `.jks`, `.env`, `key.properties`, `google-services.json`은 프로젝트 안에 두지 않는다.
2. **비밀값을 화면·로그·리포트에 출력하지 않는다.** 필요한 것은 "키가 존재하는가"이지 "키가 무엇인가"가 아니다. 값 대신 `설정됨 / 미설정`으로 보고한다.
3. **읽어야 할 때만 읽는다.** 서명 빌드나 ID 주입이 실제로 필요한 시점에만 접근하고, 확인 목적의 전체 출력(`cat .env`)은 하지 않는다.
4. **주입은 참조로 한다.** `android/key.properties`는 `.gitignore`에 넣고 `storeFile`이 `F:\keys\PDF_daeri\release.jks`를 가리키게 한다. 광고·결제 ID는 `--dart-define` 또는 빌드 시 주입을 쓴다.
5. **`.gitignore` 확인이 서명 빌드의 선행 조건이다.** `*.jks`, `key.properties`, `.env`, `local.properties`가 무시 목록에 없으면 빌드 전에 추가한다.
6. 테스트·개발 중에는 **AdMob 테스트 광고 단위 ID**를 사용한다. 실 단위 ID로 자기 광고를 클릭하면 계정이 정지된다.
7. 키를 분실하면 Play 스토어 업데이트가 불가능하다. `release.jks`를 이동·덮어쓰기·삭제하지 않는다.

## 2. 기록 원칙

- **수치를 반올림하거나 요약하지 않는다.** 판정은 아키텍트가 한다. 여기서는 원본 숫자를 전달한다.
- **실패를 성공으로 보고하지 않는다.** 테스트 3개가 실패했으면 3개 실패했다고 쓴다. 실패 전문(스택트레이스)을 보존한다.
- **추론하지 않는다.** "왜 실패했는가"가 아니라 "무엇이 출력되었는가"를 쓴다.
- 실행하지 않은 항목은 **"미실행"**으로 명시한다. 빈칸으로 두지 않는다.
- 2분 이상 걸릴 명령은 백그라운드로 실행한다.
- 실패한 명령을 반복 실행해 환경을 바꾸지 않는다. 1회 실패 → 기록 → 보고.

## 3. 1주차 기술 검증 실측 (`milestones.md`)

| # | 측정 | 기록 형식 | 판정 기준 |
|---|---|---|---|
| 1 | 100p 텍스트 PDF에서 1p 삭제 | 원본 바이트 → 결과 바이트 + 텍스트 선택 가능 여부 | 용량 감소 + 텍스트 유지 |
| 2 | 10개 PDF 합치기 | 원본 합계 → 결과 바이트 | 합계 × 1.05 이내 |
| 3 | 회전 | 원본 → 결과 바이트 | 재인코딩 없음(용량 거의 동일) |
| 4 | 혼합 문서 저장 | 성공/실패 + 에러 전문 | 성공 시 A안 승격 후보 |
| 5 | 30p 썸네일 렌더 / 50p 저장 | 밀리초 / 메모리 피크 MB | 기록 |
| 6 | 압축 프리셋 3종 | 프리셋별 원본 → 결과 + 감소율 | `min`으로 10p 스캔 ≤ 2MB |

**1·2·3 중 하나라도 실패하면 라이브러리 교체 판정 사유**다. 측정자는 판정하지 않고 수치만 넘긴다.
압축의 "본문이 읽히는가"는 사람이 판단해야 하므로 사용자 확인을 요청한다.

## 4. size_guard 유닛 테스트 픽스처

게이트 규칙은 유닛 테스트로 고정하며, 픽스처 3종으로 매 빌드 검증한다:

| 픽스처 | 내용 | 검증 목적 |
|---|---|---|
| 텍스트 PDF | 100p 텍스트 위주 | 삭제 시 용량 감소, 텍스트 보존 |
| 스캔 PDF | 이미지 위주 | 압축 대상 판별, 회전 무손실 |
| 혼합 문서 | 외부 PDF + 스캔 페이지 | `PageRef` 이원화 분기 전수 |

픽스처는 리포지토리에 커밋 가능한 크기로 만들고, 한글 파일명 검증용으로 `2026년 8월 보고서 (최종).pdf`를 포함한다.
