# PDF 앱 화면 구현 절차

## 원칙

화면은 **총 5개**다. 온보딩·튜토리얼을 만들지 않는다. 스펙이 이미 상세하므로 해석이 아니라 이행이다.
스펙에 없는 요소(정렬 옵션, 검색, 다크모드, 텍스트 선택, 주석)는 v1 제외다. 필요해 보이면 만들지 말고 묻는다.

## S1. 홈

- 상단: 앱 이름, 설정 아이콘
- 섹션 1 — **최근 연 파일**: 이름, 크기, 연 시각
- 섹션 2 — **내 문서** 2열 그리드: 썸네일 / 제목 / `12p · 3.4MB` / 날짜
- 하단 3진입점: **스캔**(주 버튼) / **PDF 열기** / **사진 → PDF**
- 최하단: 배너

인터랙션: 탭 → S4 뷰어 / 롱프레스 → 다중 선택(합치기 2개 이상, 삭제, 공유) / `⋮` → 이름 변경·나누기·압축·공유·삭제

주의:
- 정렬은 **최신순 고정**. 정렬 옵션을 만들지 않는다.
- 두 섹션을 한 그리드에 섞지 않는다.
- 최근 연 파일의 삭제는 **"목록에서 제거"** 문구를 쓴다. 앱이 소유하지 않은 파일이므로 "삭제"는 거짓말이 된다.

## S2. 스캔

ML Kit 문서 스캐너 플로우를 호출하고 **결과만 수신**한다. 자체 카메라·크롭·필터 UI를 만들지 않는다.
Play 서비스 실패 시 "사진 → PDF"로 유도하고 앱이 죽지 않게 한다.
**이 화면에는 배너를 넣지 않는다.**

## S2-b. PDF 열기

시스템 파일 선택기(SAF) 호출 → 앱 작업공간으로 복사 → S4 뷰어.
외부 인텐트(`application/pdf` VIEW) 진입도 동일 경로를 탄다.
암호 PDF는 비밀번호 입력, 손상 파일은 안내 후 종료.

## S3. 페이지 편집

진입 시 최초 1회: **"복사본으로 편집합니다. 원본은 변경되지 않습니다."**

- 3열 썸네일 그리드, 페이지 번호 표시
- 주요 액션(저장·페이지 추가)은 **상단 앱바** — 배너 근처에 두지 않기 위한 배치다
- 하단: 완충 밴드 + 배너
- 드래그 → 순서 변경 (드래그 중 배너 슬라이드 아웃)
- 탭 → 선택 모드: 회전 / 삭제 / **선택 페이지로 새 문서**(나누기)
- 페이지 추가: 카메라 / 사진
- 저장 → 제목 입력 + 화질 선택 → **용량 검증 게이트 통과** → S4

주의: 썸네일 지연 로딩. 저장 중 진행률 + 취소. 저장 후 **"새 파일로 저장됨"** 안내(원본이 바뀌었다는 오해 방지).

## S4. 뷰어

좌우 스와이프, 핀치 줌, 하단 썸네일 바. 상단: 공유, 편집으로 이동.
텍스트 선택·검색·주석 **없음**. 배너와 제스처 영역 사이에 완충 밴드.

## S5. 설정

광고 제거 구매/복원 · 기본 저장 화질 · 저장 공간 사용량 + 캐시 비우기 + 최근 파일 정리 · 오픈소스 라이선스 · 개인정보처리방침(수집 없음, 서버 전송 없음 명시).
**계정·로그인 항목 없음.**

# 광고 배치 (`banner_host.dart` 단일 구현)

배너 노출: 홈 O / 뷰어 O / 편집 O / 설정 O / **ML Kit 스캔 X / 시스템 파일 선택기 X**
저장 또는 공유 **완료 직후 전면광고 1회, 하루 최대 3회**. `ads_removed = true`면 배너·전면 모두 제거.
**기능 잠금 없음** — 무료 사용자와 결제 사용자의 기능은 동일하다.

화면마다 `AdWidget`을 직접 배치하지 않는다. 전부 `banner_host.dart`를 경유한다.

## 오터치 방지 4겹 (전부 구현해야 완성)

편집 화면은 드래그 앤 드롭이 일어나므로 오터치 위험이 가장 크다.

### 1. 높이 선점
적응형 배너 높이를 미리 계산해 `SizedBox`로 영역을 확보한다.
광고 **로드 전·로드 실패·제거 구매** 세 경우 모두 레이아웃이 동일해야 한다.
> 오터치의 최대 원인은 광고가 늦게 로드되며 발생하는 레이아웃 점프다. 이 한 겹이 나머지 셋보다 중요하다.

### 2. 완충 밴드
- 배너 바로 위에 **버튼을 두지 않는다.** 저장·페이지 추가는 상단 앱바로 올린다.
- 배너 위에 인터랙션 없는 여백 밴드를 둔다.
- 스크롤 영역 하단 패딩 = **배너 높이 + 밴드**. 마지막 썸네일이 배너 근처에 놓이지 않게 한다.

### 3. 드래그 중 배너 회피
드래그 제스처 시작 → 배너를 아래로 슬라이드 아웃(확보된 높이는 빈 공간으로 유지) → 드래그 종료 시 복귀.
**가리는 것이 아니라 치우는 방식**이다. 정책상 안전하고 화면이 흔들리지 않는다.

### 4. 전면광고 직후 배너 지연
전면광고를 닫은 뒤 수 초간 배너를 붙이지 않는다. 광고 연타 인상과 닫기 버튼 오터치를 함께 방지한다.

뷰어 화면도 핀치 줌·스와이프 영역과 배너 사이에 동일한 완충 밴드를 적용한다.

## 스토어 문구 주의

배너를 상시 노출하므로 **"광고 없음"을 차별점으로 쓰지 않는다.** 사용할 문구는 셋뿐이다:
로그인 없이 바로 사용 / 파일을 서버에 올리지 않음 / 보기·스캔·정리를 한 앱에서

## 구현 후 자체 점검

- [ ] 화면이 5개를 넘지 않는가
- [ ] 스캔·파일선택기 화면에 배너가 없는가
- [ ] 모든 배너가 `banner_host.dart`를 경유하는가
- [ ] 로드 실패·`ads_removed` 상태에서 레이아웃이 동일한가
- [ ] 배너 바로 위에 탭 가능한 요소가 없는가
- [ ] 스크롤 하단 패딩 ≥ 배너 높이 + 밴드인가
- [ ] 드래그 시 배너가 슬라이드 아웃되고 높이가 유지되는가
- [ ] 저장 후 "새 파일로 저장됨"을 알리는가
- [ ] 외부 PDF 편집 진입 시 복사본 안내가 뜨는가
- [ ] 최근 연 파일이 "목록에서 제거" 문구를 쓰는가
- [ ] 썸네일이 지연 로딩되는가 (전체 렌더링하지 않는가)
- [ ] 한글 제목·파일명이 깨지지 않고 표시되는가
